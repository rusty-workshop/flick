How a watch
becomes a tag.

Android's Host Card Emulation lets an app answer the exact commands a real NFC Forum Type 4 tag would. Flick implements just enough of that tag, and nothing else.

1

The phone asks for the NDEF app. Flick registers the standard NDEF AID, so any phone that reads tags will knock.

2

The watch hands over a capability container, then one NDEF file built from whatever preset is armed, snapshotted so a switch can't tear a message.

3

Nothing armed? It says "file not found". The watch simply isn't a tag until you want it to be.

phone00 A4 04 00 07 D2760000850101select the NDEF application
watch90 00yep, I'm a tag
phone00 A4 00 0C 02 E103select the capability container
watch00 0F 20 00 3B 00 34 04 06 E104 ...here's how to read me
phone00 B0 00 00 2Aread the NDEF file
watchD1 01 26 55 04 72 75 73 74 79 ...URI record: https://rusty.is-a.dev

Set it up.

Two pieces: a tiny editor server on any always-on Linux box, and the watch app.

The editor

# server/flick.env: FLICK_KEY=..., PORT=8480
scp server/flick.py server/editor.html \
    server/flick.env box:~/flick/
scp server/systemd/flick.service \
    box:~/.config/systemd/user/
ssh box 'systemctl --user enable --now flick'
# then open http://box:8480/#k=FLICK_KEY once

The watch

cp flick.properties.example flick.properties
# set server.key = FLICK_KEY
./gradlew :app:assembleRelease
adb install -r app/build/outputs/apk/release/app-release.apk
adb shell cmd package compile -m speed \
    -f com.rusty.flick
